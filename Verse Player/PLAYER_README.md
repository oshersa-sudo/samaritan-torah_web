# עורך חלוקת הפרקים — נגן העריכה

כלי מקומי לבדיקה וכוונון של חלוקת ההקלטות (מאיר + עדי קריאה) לפרקים שומרוניים,
עם sync דו-כיווני מול האתר החי.

## הרצה — האפליקציה הארוזה (VersePlayer.exe)

`Verse Player/VersePlayer.exe` הוא הכלי כולו בקובץ אחד: אין צורך ב-Python,
בטרמינל, בדפדפן או בזכירת כתובת. לחיצה כפולה פותחת **חלון אפליקציה רגיל**
(WebView2, המנוע שמובנה ב-Windows) — עם סמל משלו בשורת המשימות, בלי שורת
כתובת ובלי חלון קונסולה שחור. סוגרים את החלון כדי לכבות; השרת נסגר איתו.

אם WebView2 חסר במחשב כלשהו, האפליקציה לא נופלת — היא נפתחת בדפדפן במקום.

**איפה הוא מחפש את ההקלטות** (לפי הסדר): משתנה הסביבה `TORAH_ROOT` ← קובץ
`verse-player.ini` לצד ה-exe (שורה אחת: `root=C:\נתיב\לפרויקט`) ← שתי רמות
מעל ה-exe ← מיקומים מוכרים. אם לא נמצא — מוצגת הודעה מסבירה, לא קריסה.

**בדיקה עצמית**: `VersePlayer.exe --selftest` מוודא שהוא מוצא את הפרויקט,
טוען את השרת, מצליח לבנות מחדש את דף הנגן, ושחלון WebView2 זמין — שימושי
כשמשהו לא עולה. הדוח מוצג בחלונית וגם נכתב ל-`selftest.txt` לצד ה-exe;
הוסף `--quiet` כדי לדלג על החלונית (למשל בהרצה אוטומטית).

ה-exe אינו נשמר ב-git (ניתן לבנייה מחדש). לבנייה:

```
py -3 -m PyInstaller --noconfirm --onefile --noconsole --name VersePlayer --icon "Verse Player/app.ico" --paths "Verse Player" --hidden-import player_server --hidden-import build_player --hidden-import audio_analysis --hidden-import numpy --collect-submodules yt_dlp --collect-all webview --collect-all pythonnet --hidden-import clr "Verse Player/verse_player_app.py"
```

(`app.ico` נוצר מ-`web/static/img/icon-512.png`.)

## הרצה — מתוך הקוד

**קיצור-דרך**: הרץ (או צור קיצור-דרך אליו בשולחן העבודה) את
`Verse Player/run_player.bat` — פותח את הדפדפן וגם מפעיל את השרת
בבת אחת. סוגרים את חלון ה-cmd כדי לכבות את השרת.

או ידנית:

```
python "Verse Player/player_server.py"
```

(דורש Python 3 — למשל `C:\Users\osher\AppData\Local\Programs\Python\Python313\python.exe`)

ואז פתח בדפדפן: **http://localhost:8934/**

חשוב לפתוח דרך הכתובת הזו (לא double-click על player-all.html) — כפתורי הסנכרון
צריכים שרת ב-same-origin כדי לעבוד (fetch מ-`file://` נחסם ע"י הדפדפן).

## מה יש בנגן

- **בורר ספר/קורא** — מאיר בן יפנה ששוני או כל אחד מ-7 עדי הארכיון.
- **רשת פרקים** — לחיצה פותחת את קבוצת העריכה (פרשה שלמה למאיר; קובץ ארכיון אחד לעד).
- **פס גרירה עם קווי גבול** — כל גבול בין קטעים מסומן בקו אנכי; הגבולות של הקטע
  המתנגן כרגע מודגשים בכתום. תצוגת "קטע נוכחי" מציגה תמיד התחלה/סוף/זמן שנותר,
  עם כפתורי קפיצה לתחילת/סוף הקטע.
- **לכל קטע: עריכת התחלה וסוף בנפרד** — כפתורי כוונון ±0.1/±0.5/±1 שנ' לכל גבול,
  עם השמעה. בפרשת מאיר הגבולות רציפים (סוף קטע = התחלת הבא), כך שעריכת אחד מזיזה
  גם את השני.
- **פעולות**: ✂ פיצול בנקודת הנגן, ⤵ איחוד עם הקודם, 🔢 מספור מחדש ברצף, ↶ ביטול.

## נורית סנכרון לכל פרק

בפינת כל תא ברשת הפרקים: נקודה ירוקה = הקטע (לפי מספר הפרק בחלוקה השומרונית)
זהה בין המצב המקומי לענן החי (אורך + טווח פסוקים + שם קובץ); אדומה = שונה או
חסר בענן. הבדיקה מרוענת אוטומטית בכל טעינה/מעבר ספר/קורא, וגם ~2 דקות אחרי
"🚀 דחוף לענן" (זמן טיפוסי לסיום הפריסה ב-Render). כפתור "🔄 בדוק" ליד המקרא
מרענן ידנית. אינדיקציה — לא חסימה: אפשר לערוך/להאזין גם לפרק "אדום".

## סנכרון מול הענן

- **🔄 סנכרן חלוקות מהענן** — מושך `portions`+`sam_chapters` מ-
  `https://samaritan-torah.onrender.com/api/...` ומרענן שיוך פרשה + פתיח לתצוגה
  בלבד. **כיוון אחד: ענן ← נגן.** לא נוגע בעריכות פעילות (`edits`), לא חותך אודיו.

- **☁️ החל שינויים (חיתוך + מניפסט מקומי)** — כפתור בתוך עורך הקבוצה. שולח את
  הקבוצה הפתוחה ל-`POST /api/apply`: חותך/מעתיק MP3 לפי הגבולות החדשים, מרענן
  verses/incipit/sam_ch_id/portion מה-DB המקומי + מה-API החי, מעדכן
  `readings.json`/`witnesses.json`, בונה מחדש את player-all.html. **לא דוחף ל-git.**
  אחרי הצלחה הדף נטען מחדש אוטומטית (כדי שקבוצות אחרות יראו קבצים/שמות עדכניים).

- **🚀 דחוף הכל לענן (git push)** — `git add -A` על תיקיות ההקלטות, commit, ו-
  `git push private web-deploy:main`. זה מה שבפועל מעדכן את האתר החי (Render
  פורס אוטומטית תוך כמה דקות). דוחף את **כל** מה שהוחל עד כה, לא רק קבוצה אחת.

זרימת עבודה טיפוסית: פתח פרק → כוון גבולות/מספרים תוך האזנה → "☁️ החל שינויים"
(בודק שהכל תקין מקומית, אפשר להאזין להקלטה שנחתכה) → המשך לפרקים נוספים → כש
מוכן, "🚀 דחוף לענן" פעם אחת בשביל כל השינויים המקומיים המצטברים.

## הורדה מחדש וחלוקה אוטומטית

בתוך עורך קבוצת מאיר: **📥 הורדה מחדש וחלוקה אוטומטית**. שואל כתובת YouTube או
נתיב לקובץ מקומי, מוריד/קורא אותו (yt-dlp, רץ בתוך התהליך עם `--no-playlist`
ו-`--js-runtimes node`), ומריץ את **אותו אלגוריתם המקורי** (`audio_analysis.py`, מחולץ מ-
batch_genesis.py): זיהוי הפסקות (≥0.45 שנ') + ירידת מנגינה בסיום כל פרק (ירידה
של ≥2.5 חצאי-טון בגובה הצליל) + תכנות דינמי שמעגן את הבחירה סביב מיקומים
צפויים לפי יחס אורך-הטקסט של כל פרק (מה-DB המקומי) — בדיוק כמו ש-refit.py עשה
ידנית כל הפרשות ה"חלשות" הערב.

התוצאה **לא נכתבת ל-readings.json** — נטענת כקבוצה חדשה עם תווית "(הורדה
מחדש)" ואזהרה, כדי שתסקור/תכוון עם כל כלי העריכה הרגילים (כולל "☁️ החל
שינויים" הרגיל) לפני שהיא הופכת קבועה. אם מספר הגבולות ה"חלשים" (בלי ירידת
מנגינה ברורה) גבוה — כדאי להאזין להם בקפידה לפני החלה.

**שים לב לבאג שהיה כאן**: הקוד הריץ `sys.executable -m yt_dlp`. באפליקציה
הארוזה `sys.executable` הוא ה-exe עצמו, כך שהלחיצה הפעילה **עותק שני של
התוכנה** במקום להוריד. ההורדה רצה עכשיו בתוך התהליך דרך מנוע הפקודות של
yt-dlp עצמו — אותם דגלים בדיוק, בלי הרצת תהליך חיצוני.

## הגנות שנבנו לתוך player_server.py (מבוססות על באגים אמיתיים שנתפסו)

- **קבוצת מאיר**: הקטעים חייבים לכסות את כל ציר הזמן ברציפות (0 עד סוף) בלי
  פערים/חפיפות — אחרת הבקשה נדחית. מונע איבוד שקט של אודיו.
- **קבוצת עד**: אם קובץ ארכיון מכיל כמה פרקים לאותו קורא (נפוץ!), ה-payload
  חייב לכלול את כולם — אחרת הבקשה נדחית עם רשימת הפרקים החסרים. פרקים
  "multi-file" (שממשיכים גם בקובץ אחר) שומרים את הקטע בקובץ האחר.
- כל קובץ פלט מאומת מול האורך הצפוי (±0.3 שנ') לפני שהוא נכתב.
- שם קובץ הפלט תמיד עם padding תלת-ספרתי אחיד (`c092` לא `c92`/`c0092`) — מנע
  כמה תקלות ליליות של דריסת קבצים בטעות.

## העברת פרק לפרשה שכנה

פרשה היא רצף פרקים, ולכן רק הקצוות זזים: הפרק **הראשון** בפרשה יכול לעבור
לקודמת (⇤), והפרק **האחרון** לבאה (⇥). זו הזזה של הגבול בין שתי פרשות בצעד
אחד — פרק מהאמצע היה קורע חור בתוך הפרשה, ולכן הכפתורים מופיעים רק בשתי
השורות האלה. השרת בודק שוב ודוחה גם אם הדף יבקש אחרת: פרק מהאמצע, כיוון
הפוך, פרשה שתתרוקן, פרק המורכב מכמה קטעי מקור, או שם קובץ תפוס.

ההעברה משנה את שם ההקלטה לסדרת הפרשה החדשה ולוקחת את זהות הפרשה **מהאתר
החי**, מגבה את `readings.json`, ומחזירה אותך לפרק במיקומו החדש.

## שחזור מטעות

אם `apply` יצר משהו לא רצוי לפני push: `git checkout -- <קובץ>` משחזר את
המצב המחויב האחרון (readings.json/witnesses.json/כל mp3). אם כבר עשית push,
`git revert` על ה-commit הרלוונטי.

## קבצים

- `build_player.py` — בונה את `web/player-all.html` מ-`readings.json`+`witnesses.json`.

  אוטומטית אחרי `/api/apply`).
- `player_server.py` — השרת המקומי (סטטי + שני ה-endpoints של הסנכרון).
